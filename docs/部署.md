# 如何部署

这套系统分成两段，**不要把 OCR 和问答绑在同一次启动里**。

```
本机 / CI（做一次）                    服务器（长期跑）
─────────────────                    ──────────────
PDF 扫描件
  → python -m pdf_rag ingest         data/index/ + data/book.pdf
  → 得到 data/index/                   → python -m pdf_rag serve
                                       或 docker compose up
```

`ingest` 要装 Tesseract、跑十几分钟、写出几百 MB 索引。线上容器只读这些文件，回答问题时调 embedding API 和 Grok。

---

## 1. 服务器上必须换官方 API Key

本机可以 `grok login`，用 CLI 代理答题。  
**服务器不要这么干**：登录态大约 7 天过期，还依赖本机 `~/.grok/auth.json`。

生产在 [console.x.ai](https://console.x.ai) 建一把 `xai-...`，放进环境变量。有 `XAI_API_KEY` 时，程序自动走官方 API（`api.x.ai` + `grok-4.6`）；没有才退回 CLI 代理。

`.env` 示例（不要提交到 Git）：

```bash
# 答题（生产必填）
XAI_API_KEY=xai-你的密钥
XAI_MODEL=grok-4.6

# 向量检索（已有 embeddings.npy 时，提问也会再 embed 一次问题）
DASHSCOPE_API_KEY=sk-你的密钥
DASHSCOPE_EMBED_URL=https://llm-e4ealg1c1ytymvji.cn-beijing.maas.aliyuncs.com/api/v1/services/embeddings/text-embedding/text-embedding
DASHSCOPE_EMBED_MODEL=qwen3.7-text-embedding
```

国内机器访问 `api.x.ai` 常常要代理，可在同一份 `.env` 里加：

```bash
HTTPS_PROXY=http://127.0.0.1:7897
HTTP_PROXY=http://127.0.0.1:7897
```

## 2. 先在本机把数据准备好

```bash
cd pdf-rag-1080
source .venv/bin/activate
python -m pdf_rag ingest "/绝对路径/13005软件工程_2024年版(张琼声).pdf"
```

完成后至少要有：

```
data/book.pdf              # 教材副本或符号链接，网页右侧预览用
data/index/pages.jsonl
data/index/chunks.jsonl
data/index/bm25.pkl
data/index/meta.json
data/index/embeddings.npy  # 可选，没有就只走 BM25
```

这些目录默认不进 Git。部署时用 `rsync` / `scp` 拷到服务器，或挂进 Docker 数据卷。

```bash
rsync -avz data/ user@server:/opt/pdf-rag-1080/data/
```

## 3. 方式一：服务器直接跑 Python

适合一台 Linux VPS。

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-venv python3-pip

git clone https://github.com/cmdfas/pdf-rag-1080.git /opt/pdf-rag-1080
cd /opt/pdf-rag-1080
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 把本机 ingest 好的 data/ 拷进来，再写 .env
nano .env

python -m pdf_rag serve --host 0.0.0.0 --port 8000
```

浏览器打开 `http://服务器IP:8000`。  
`/api/health` 里应看到 `"index_ready": true` 且 `"chat_backend": "api"`。

用 systemd 保活：

```ini
# /etc/systemd/system/pdf-rag.service
[Unit]
Description=PDF textbook RAG
After=network.target

[Service]
WorkingDirectory=/opt/pdf-rag-1080
EnvironmentFile=/opt/pdf-rag-1080/.env
ExecStart=/opt/pdf-rag-1080/.venv/bin/python -m pdf_rag serve --host 127.0.0.1 --port 8000
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now pdf-rag
```

前面再加 Nginx 反代与 HTTPS：

```nginx
server {
    listen 443 ssl;
    server_name rag.example.com;
    client_max_body_size 80m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_read_timeout 180s;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
```

问答接口最长可能要一分钟（检索 + 模型），超时不要设太短。

## 4. 方式二：Docker Compose（推荐）

本机或服务器都可以。镜像里**没有 Tesseract**，只提供网页服务。

```bash
# 1. 本机已经 ingest 出 data/
# 2. 写好 .env（含 XAI_API_KEY、DASHSCOPE_API_KEY）
docker compose up -d --build
```

默认映射 `8000:8000`，数据卷 `./data:/app/data`。

```bash
curl -s http://127.0.0.1:8000/api/health
```

更新代码：

```bash
git pull
docker compose up -d --build
```

索引变了（重新 ingest）只要覆盖 `data/`，不用重建镜像。

---

## 5. 不要在生产环境做的事

- 不要在线上对 228 页扫描件现场 OCR（慢、要中文 Tesseract、占 CPU）。
- 不要把 `.env`、教材 PDF 提交到 GitHub。
- 不要用 `grok login` 当生产鉴权。
- 不要把 `data/index` 打进镜像（镜像会膨胀，且一本书一镜像）。

---

## 6. 检查清单

| 检查 | 期望 |
|---|---|
| `GET /api/health` | `index_ready: true` |
| `chat_backend` | 生产应为 `api` |
| `embeddings_ready` | `true` 才会混合检索 |
| `GET /book.pdf` | 能下载/预览教材 |
| `POST /api/ask` | 返回答案和页码行号 |

本地开发仍可不配 `XAI_API_KEY`，继续 `grok login` 走 CLI 代理。
